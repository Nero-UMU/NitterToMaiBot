# NitterToMaiBot

通过 Nitter 获取推特内容，并由 MaiBot 转发到 QQ 群。

## 基本功能

- 每个 QQ 群可以独立订阅多个推特账号，也可以独立暂停或恢复推送。
- 每条群账号订阅可选择“全部推文”或“仅媒体”；仅媒体模式会排除纯文本推文。
- 扫描账号之间默认等待 2 秒；完整扫描结束后，再等待 300 秒（5 分钟）开始下一轮。新推文及媒体暂存到服务器，群转发独立计时，默认每 600 秒（10 分钟）打包发送已暂存的内容。
- 自动订阅直接用服务器缓存组装群聊天记录，不先发送给机器人自己；单条推文也使用聊天记录，视频和图片放在同一份聊天记录中。
- 同群更新按原推文顺序合并，媒体累计超过分包阈值（默认 10 MiB）或 100 个消息节点时分包，不重排推文；单条推文自身媒体合计超限时保持完整、独立发送。开启失败链接汇总后，存在最终转发失败的推文或附件时，在本轮最后追加一份原文链接聊天记录。
- 待转发推文、媒体缓存和失败记录会持久化，重载后继续使用；可设置北京时间静默时段，期间继续检查和缓存，群转发延期到静默结束且发送周期到期后进行。
- 支持在 QQ 群聊和私聊中获取指定账号的最新推文或解析指定推文链接。
- 单条推文的正文和全部图片合并为一条图文消息，不逐张另发；聊天记录内也保持每条推文的正文和图片同节点。
- 默认自动解析群聊和私聊新正文中的推文链接，忽略引用消息中的链接；识别成功后会阻止 LLM 重复回复该链接。
- 可使用 MaiBot 已配置的模型把推文正文翻译成简体中文，并附在原文下方。
- 每轮处理 Nitter 当前返回的全部未处理推文；支持设置是否转发账号的转推、媒体大小上限和每群订阅上限。
- 可选择仅群命令、仅后台或两者共同管理订阅；群命令和后台始终使用同一份订阅数据。
- 可选将成功转发的推文摘要或完整文本、真实 QQ 消息 ID 和图片预览写入对应聊天上下文；用户引用时自动补入原内容，插件重载后仍可恢复近期转发记录。

## 快速开始

### 安装插件

进入 MaiBot 的 `plugins` 目录并克隆本项目：

```bash
cd /path/to/MaiBot/plugins
git clone https://github.com/Nero-UMU/NitterToMaiBot.git
```

等待 MaiBot 识别并加载插件，然后在后台插件管理页面打开“Nitter 推文转发”。

插件依赖会按照 `_manifest.json` 由 MaiBot 安装，无需手动安装 Python 包。首次加载时，Runner 会根据插件配置模型生成本地 `config.toml`。

自动订阅需要启用提供公开 `adapter.napcat.action.call` API 的 NapCat/Snowluma 适配器；通过 SDK 调用，不需要额外填写 OneBot HTTP 地址或密钥。更新后请允许新增的 `api.list`、`api.call` 和 `send.hybrid` 能力。

如需转发 Nitter HLS 视频，服务器还需安装 `ffmpeg`。Ubuntu/Debian 可执行：

```bash
sudo apt install ffmpeg
```

插件 ID 为 `github.nero-umu.nitter-to-maibot`；从旧 ID 升级时，插件会自动迁移原有订阅和去重状态。

### 基本设置

在 MaiBot 后台打开本插件并完成以下设置：

- **启用插件**：开启自动扫描、自动转发和自动链接解析。
- **Nitter 实例地址**：默认使用 `https://nitter.net`，也可以填写自己的 Nitter 地址。
- **发送机器人 QQ 号**：仅在 MaiBot 同时接入多个 QQ 机器人时需要指定。
- **更新检查间隔（秒）**：默认 `300`，完整扫描全部账号后再等待该时长开始下一轮，与账号间等待、请求和媒体处理耗时叠加。
- **账号扫描间隔（秒）**：默认 `2`，相邻账号之间的等待时间；设置为 `0` 时不等待，账号读取失败后也会等待再继续下一个。
- **群转发间隔（秒）**：原“轮询间隔”，沿用已有数值，默认 `600`；将此周期内暂存的推文按群统一打包发送。
- **手动获取合并阈值**：默认 `1`，仅控制 `/推特推文`；自动订阅始终使用聊天记录。
- **发送失败二分次数**：默认 `3`；设置为 `0` 时合并转发包首次失败便全部放弃，设置为 `1` 时最多拆成两个子包各重试一次，以此类推。
- **汇总发送失败的推文链接**：默认开启，可在“Nitter 订阅”中关闭。开启后，在群转发周期末将整个周期内最终失败的推文或附件对应的 `x.com` 原文链接去重并打包发送；重试成功的不列入，汇总自身失败时不递归重试。
- **启用静默时段**：默认关闭；默认范围为北京时间 `00:00`–`06:00`，期间继续检查并缓存到服务器，只暂停群转发；已到期的群转发会在静默结束后的调度中发送。
- **启用推文翻译**：默认关闭；开启后为自动推送、手动获取和链接解析结果增加中文翻译；翻译失败时继续发送原文，并在翻译区域显示“翻译错误”。
- **翻译模型**：选择 `utils`、`replyer` 或 `planner` 模型任务，推荐使用 `utils`。
- **翻译提示词**：默认已填写内置翻译要求，可以在后台直接修改并用于之后的所有推文翻译。
- **合并转发分包阈值（MiB）**：原“媒体大小上限”，默认 `10`，沿用原配置键 `delivery.max_media_size_mb` 和已有数值。自动订阅及手动多推文转发按已缓存图片、视频和文件的原始大小累计，加入下一条推文会超限时先发送当前包；恰好等于阈值仍放在同一包。例如 `1、3、8、2 MiB` 按顺序分为 `4 MiB` 和 `10 MiB` 两包，不重排填充。单条推文本身合计超限时不拆散，独立发送；文字和协议开销不计入媒体体积。此配置仍保留原有的单附件下载上限，HLS 视频优先选择不超过该上限的最高可用清晰度。
- **订阅管理方式**：默认为“仅群命令”；也可改为“仅后台”或“群命令和后台”，后台保存时会校验群号、账号及引用关系。
- **让机器人知道已转发推文**：默认关闭；开启后只在推文成功发送时写入对应 Maisaka 聊天上下文，可选择摘要或完整文本。两种模式均保留真实 QQ 消息 ID 和已发送图片的预览；用户引用时补入对应内容，不会再次转发推文。图片描述通过 MaiBot 已配置的 `vlm` 模型在后台生成，供纯文本模型理解；未配置或识图失败时明确保留“画面尚未识别”，不猜测画面。视频只记录附件信息，不识别视频画面。

扫描和群转发由独立后台任务运行。即使仍在扫描其他账号或等待下一轮，到了群转发时间也会发送当前已就绪的推文；尚未完成暂存的推文进入后续转发周期。

订阅媒体保存在插件数据目录的 `media_cache` 中，多群投递和二分重试复用同一份文件，全部目标群处理完成或最终放弃后清理对应缓存。无需额外 HTTP 服务；NapCat 必须能访问缓存的绝对路径，分机部署时需共享相同路径。

开启上下文同步后，插件另将已发送消息的文字、图片预览及识图结果保存在数据目录的 `sent_context.db` 中，按真实聊天流隔离，保留最近 200 条、至多 128 MiB 的记录。图片预览只取首帧、最长边不超过 1024 像素，不影响 QQ 中实际发送的图片质量。超过 SDK 单帧上限的风险通过分组注入规避。正文或部分附件成功时，仅记录实际发送成功的内容，并注明失败附件。

重启或上下文裁剪后，用户引用这些已保存的消息时会重新注入；正在识图时最多等待 20 秒，识图继续在后台完成。升级前、开关关闭期间或已经超出保留范围的转发没有此关联记录，无法自动恢复。纯文本模型通过图片描述理解内容，视觉模型还可读取图片预览；此功能不修改 MaiBot 原生消息库或原生后台识图流程。

使用“仅群命令”时请通过下面的群内命令管理订阅；使用“仅后台”或“群命令和后台”时，也可以在后台的“订阅列表”中维护群号与账号对应关系。

### Nitter 实例说明

公共实例 `https://nitter.net` 的访问速度和稳定性可能因网络环境、访问频率等因素受到影响，可能出现响应缓慢、超时或请求受限。

如果需要更稳定地轮询大量订阅，建议参考 [Nitter 官方项目](https://github.com/zedeus/nitter) 自行部署实例，然后在插件后台将“Nitter 实例地址”修改为该实例的地址。

请确保运行 MaiBot 的服务器能够直接访问填写的地址。

## 命令

- `/推特帮助`：查看全部可用命令、参数和简要说明。英文别名：`/twitter_help`。

### 订阅管理命令

以下命令只能在 QQ 群聊中使用：

- `/推特关注 <账号1> [账号2 ...] [仅媒体]`：为当前群订阅一个或多个推特账号，单次最多添加 10 个；账号可带或不带 `@`。命令末尾添加 `仅媒体` 时，本次列出的全部账号只推送带图片、视频或 GIF 的推文；对已订阅账号再次使用该命令可以切换模式。英文别名：`/twitter_follow`。
- `/推特取关 <账号1> [账号2 ...]`：取消当前群对一个或多个账号的订阅。英文别名：`/twitter_unfollow`。
- `/推特订阅查询`：查看当前群的推送状态、订阅账号、推特名称及 `[全部推文]`/`[仅媒体]` 标签；超过 20 个账号时自动使用 QQ 合并转发。英文别名：`/twitter_follows`。
- `/推特仅媒体 on|off`：一键修改当前群的全部账号；`on` 统一设为 `[仅媒体]`，`off` 统一恢复为 `[全部推文]`。英文别名：`/twitter_media_only on|off`。
- `/推特推送 开启|关闭`：开启或暂停当前群的自动推送，不会删除已有订阅。英文别名：`/twitter_push on|off`。

### 推文获取与解析命令

以下命令可在 QQ 群聊或私聊中使用：

- `/推特推文 <账号> [数量]`：获取该账号最新的若干条推文；数量默认为 `1`，且不会改变自动轮询的去重记录。超过手动获取合并阈值时，正文、图片和视频一起打包进聊天记录，不再把视频单独发送。英文别名：`/twitter_posts`。
- `/推特解析 <推文链接>`：解析一条 Twitter、X 或 Nitter 推文链接，并发送正文及媒体。英文别名：`/twitter_parse`。

开启“自动解析推文链接”后，也可以直接在群聊或私聊中发送推文链接，无需输入 `/推特解析`。

### 运行命令

- `/nitter_status`：查看插件是否启用、Nitter 地址、订阅数量、静默状态、待发送数量、手动获取合并阈值、更新检查间隔和群转发间隔。
- `/nitter_scan`：手动立即检查并转发当前积压，不必等待群转发周期；静默期间只缓存到服务器，不会绕过静默设置。

## 使用示例

```text
/推特关注 elonmusk OpenAI
/推特关注 shouu_kyun r_ws2l 仅媒体
/推特订阅查询
/推特仅媒体 on
/推特推文 elonmusk 3
/推特解析 https://x.com/elonmusk/status/1234567890
/推特推送 关闭
```

## 权限与能力

- `chat.open_session`：打开目标 QQ 群的真实聊天流。
- `api.list`、`api.call`：发现已启用的 QQ 适配器，通过其公开 API 直接发送服务器缓存组成的群聊天记录。
- `send.text`、`send.image`、`send.custom`：发送推文正文、图片、视频和其他附件。
- `send.hybrid`：将单条推文的正文和全部图片合并发送为一条消息。
- `send.forward`：发送多条推文或较长订阅列表的 QQ 合并转发。
- `llm.generate`：开启推文翻译后调用所选模型任务；开启上下文同步后，通过 `vlm` 任务生成已发送图片的描述。
- `maisaka.context.append`：仅在开启聊天上下文同步后，将已成功转发的推文图文记录及引用关联信息加入对应聊天流。

插件没有向 LLM 注册 Tool；聊天交互由命令和推文链接拦截处理。

## 故障排查

- **插件未出现或加载失败**：确认目录为 `plugins/NitterToMaiBot/`，并检查 MaiBot、插件 SDK 版本和加载日志。
- **Nitter 返回 404 或连接失败**：在服务器上确认配置的 Nitter 实例可访问，并检查实例是否支持目标账号和状态页；公共实例不稳定时可以切换到自建实例。
- **没有自动推送**：确认插件、当前群推送和账号订阅均已开启；同时检查轮询间隔、静默时段和 `/nitter_status` 中的待发送数量。
- **命令无法使用**：群订阅修改命令只能在 QQ 群聊中执行，并受“订阅管理方式”“群订阅命令总开关”和“仅限本地操作员管理”设置影响。
- **后台订阅修改未生效**：确认“订阅管理方式”为“仅后台”或“群命令和后台”；如果页面已过期，请刷新后台后重新编辑，避免覆盖较新的群内订阅。
- **链接仍交给 LLM**：确认插件已启用，并开启“自动解析推文链接”。
- **翻译模型返回内容安全错误**：推文正文和原文链接可能触发模型服务商风控，可关闭翻译或更换模型任务。
- **图片或视频发送失败**：检查媒体大小上限、Nitter 媒体地址、服务器是否安装 FFmpeg，以及 QQ 适配器是否正常运行。

## 注意事项

> 插件会在聊天窗口中发送推文内容和原文链接，这些信息可能进入聊天上下文，并触发部分模型服务商的内容安全策略。请根据实际使用环境谨慎选择模型。
